Quick start: send your first request

If you have used Postman you will feel at home within minutes. The desktop app uses forms, so you do not need to learn JSON first. Everything is saved as plain files you can keep in git and run in bulk from the command line.

Download requestbabyComing from Postman

Five steps to your first request

  1. Download and open the desktop app, choose “New project” and give it a name.
  2. Click “New” in the sidebar → case, pick HTTP / HTTPS and fill in a name and URL. You can also paste a command copied with “Copy as cURL” from the browser.
  3. On the Request tab fill in the method, URL, query parameters, headers and body. Every row has a switch, so you can turn one off temporarily instead of deleting it.
  4. Click “Send” at the top right and read the status, time, body (formatted or raw), headers and the equivalent cURL command in the response area.
  5. On the response’s Fields tab hover a field and click “Assert value” or “Assert type” to create an assertion, or “Capture…” to store it as a variable for later requests. Then click “Run all” to run every case at once.

Prefer the command line? requestbaby init myapi creates a project, requestbaby send <case file> sends one case and requestbaby run runs them all.

What you use day to day

Build requests

Any HTTP method, with URL, query parameters and headers edited row by row. Bodies can be JSON, x-www-form-urlencoded, form-data (including file upload) or raw text, in the same order as Postman.

Environments and variables

dev / test / prod each have their own addresses and accounts, referenced as {{baseUrl}} in requests. Passwords and tokens can be marked secret: they stay on your machine and show as **** in logs and reports.

Pass values between requests

Store the token from a login as a variable and use it in later requests. Cookies are saved and sent automatically. Put a shared header such as Authorization on the collection once and every case under it inherits it.

Bulk runs and results

“Run all” runs everything and shows pass or fail per case. A failure says what was asserted, what was expected and what came back. Chain cases into flows, repeat them over CSV / JSON data, and keep a run history.

Advanced settings

Each request can set its own timeout, retries, redirect following and certificate checking. The whole project can go through a socks5 / http proxy, or switch it off in one click.

Import what you have

Import existing endpoints from cURL, Postman collections and OpenAPI / Swagger instead of retyping them. Beyond HTTP you can also test gRPC and WebSocket.
