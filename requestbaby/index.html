AI 写的代码，多到没人读得完。

逐行审查已经跟不上 AI 的产出速度。信任需要换一种来源：一套独立于实现、由你自己握有的验收标准，加上可以重复运行的证据。requestbaby 做的就是这件事，让人在接受 AI 交付之前，有据可依。

独立于实现。

用例是纯 JSON，从接口边界和界面外部去验，不依赖被测代码的内部结构。AI 可以读，也可以写，但断言是你定的，不会被悄悄放宽。

接口和界面，一起验。

HTTP / HTTPS、gRPC、WebSocket 接口，Web 页面和 Android 应用，放在同一个项目里。断言状态码、响应头和响应体里的任意字段，登录得到的 token 存成变量供后面使用。

每一步，都有证据。

界面的每一步自动截图，框出点了哪里、验证了哪个元素；失败时另存页面、控制台和网络请求。运行历史记录对应的代码提交，同一提交上时过时不过的用例会标成“不稳定”。

同样的用例，同样的结论。

判断通过与否不调用大模型，不消耗 token。命令行退出码就是结论，一行命令放进 CI；单个可执行文件，运行时不依赖其他软件。

结论带着证据，一眼看懂差在哪。

接口用例失败时，直接告诉你断言了什么、期望什么、实际是什么；界面用例的每一步都有截图，红框标出点了哪里、验证了哪个元素。

能验收什么。

接口

HTTP / HTTPS、gRPC（服务端反射或 .proto 文件，不用生成代码）、WebSocket（逐步发送、接收、断言）。dev / test / prod 各有一套地址和账号，密钥放在不入库的本机文件里。可以把多个集合串成流程，也可以按多组数据重复运行。

Web 界面

直接驱动本机的 Chrome / Edge，不需要 Playwright 或 Node，也可以连 Docker、云端的远程浏览器。按人看到的样子找元素（名叫“登录”的按钮、标签是“手机号”的输入框），自动等元素就绪再操作，不用写 sleep。

Android 应用

通过 adb 操作真机或模拟器，远程模拟器、云手机也可以。同样按角色和文字定位，失败时保存界面结构和 logcat。

现有资产

从 OpenAPI / Swagger / Postman / cURL 导入现成的接口。所有对外连接可以统一走代理（socks5 / http），也可以一键关掉。

所有安装包见下载页。

日常调接口，该有的都有。

先把它当成一个顺手的接口调试工具来用就够了，不需要先理解“验收”。

  • 用表单构造请求：任意方法、查询参数、请求头，Body 支持 JSON、表单、form-data 文件上传和 raw 文本。
  • 看清响应：状态码、耗时、响应体（格式化 / 原始）、响应头，还能看到等价的 cURL。
  • 环境与变量：dev / test / prod 各一套地址和账号；登录拿到的 token 存成变量，后面直接用；Cookie 自动保存。
  • 集合与批量运行：用例按目录分组，公共请求头只写一次，一键运行全部并看到每个用例的结果。
  • 从 cURL、Postman、OpenAPI / Swagger 导入现成的接口。

快速上手

一个用例，就是一个 JSON 文件。

放在 collections/ 下，文件名顺序就是运行顺序。下面这个用例向 baseUrl 的 /auth/login 发一个 POST，期望状态码是 200、code 等于 0、data.token 是字符串，并把 token 存起来，后面的用例写 {{token}} 就能用。失败时报告会直接写出：body.code = 0 → 期望 0，实际 4030001。

{
  "name": "登录",
  "request": {
    "method": "POST",
    "url": "{{baseUrl}}/auth/login",
    "body": { "json": { "username": "{{username}}", "password": "{{password}}" } }
  },
  "expect": {
    "status": 200,
    "body": { "code": 0, "data.token": { "type": "string" } }
  },
  "capture": { "token": "data.token" }
}

界面用例的写法类似，把请求换成一步一步的操作。Android 把 web 换成 android，写应用包名和步骤即可：

{
  "name": "登录后看到订单",
  "web": {
    "url": "{{webBase}}/login",
    "steps": [
      { "fill": { "label": "手机号" }, "value": "{{phone}}" },
      { "fill": { "label": "密码" }, "value": "{{password}}" },
      { "click": { "role": "button", "name": "登录" } },
      { "expect": { "role": "heading", "name": "我的订单" } }
    ]
  }
}

开始很轻，三步到证据。

  1. 写下期望

    自己写，或让 AI 读 requestbaby guide 那页写法速查后代写；也可以直接导入 cURL、OpenAPI、Postman。

  2. 真的跑一遍

    requestbaby run 跑全部用例，requestbaby verify 依次校验、跑用例、跑流程，给出一个结论。

  3. 看证据，做决定

    在桌面端或 HTML 报告里查看响应记录和每一步截图，再决定接受还是打回。

requestbaby init myapi && cd myapi                          # 生成项目：dev / prod 环境、示例用例
requestbaby vars set baseUrl http://localhost:8080 -e dev   # 告诉它被测服务在哪
requestbaby send collections/orders/01-创建订单.json --suggest   # 发一次，看真实响应，并给出断言建议
requestbaby run                                             # 跑全部用例
requestbaby open                                            # 在桌面端打开这个项目

命令行和桌面端读写同一个项目目录，桌面端里的每个操作都有对应的命令。

开始前，你可能想知道

requestbaby 是用来做什么的？

AI 写的代码越来越多，没人能逐行读完。requestbaby 让你自己握有一套验收标准：把「发什么请求、点哪些按钮，应该得到什么结果」写成 JSON，让它真的跑一遍，用通过或失败、响应记录和每一步的截图来决定接不接受这次交付。

它和 Postman、Playwright 是什么关系？

它们是顺手的开发工具，requestbaby 站在验收这一侧：用例是纯 JSON，与被测代码相互独立，AI 也读得懂、写得出；接口和界面在同一个项目里验收，结论带证据。已有的 Postman、OpenAPI、cURL 可以直接导入。界面验收直接驱动本机的 Chrome / Edge，不需要安装 Playwright 或 Node。

只想日常调接口，能当 Postman 用吗？

可以。桌面端用表单构造请求（方法、参数、请求头、JSON / 表单 / 文件上传 Body），支持环境变量、token 传递、Cookie、集合、批量运行、从 cURL / Postman / OpenAPI 导入，上手不需要写 JSON。目前没有 Mock Server、云端团队空间、OAuth 向导和 Postman 脚本迁移，详见快速上手。

判断通过与否会调用大模型吗？

不会。通过与否只看你写下的断言，不调用大模型，不消耗 token，同样的用例每次得到同样的结论。

收费吗？数据会上传吗？

免费，开源，MIT 许可。用例、响应、截图和历史都保存在你自己的项目目录里，没有账号，没有使用统计。详见隐私说明。

支持哪些平台？

桌面端支持 macOS 12 及以上（已签名并通过 Apple 公证）。命令行支持 macOS（Apple 芯片、Intel），可以放进 macOS 的 CI。Linux 和 Windows 暂时没有安装包。

怎么放进 CI？

运行 requestbaby verify：依次校验、跑全部用例、跑全部流程，退出码 0 表示全部通过，1 表示有用例失败，2 表示无法完成验证。加 --report json 或 html 得到报告。
